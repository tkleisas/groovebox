# NSR-2 — Compact Panel Variant

NSR-2 is the compact sibling of NSR-1 (this repo's `design.md` rev A).
Same architecture: Pi Zero 2W brain + Pico panel module as a USB-MIDI
device, yawn engine, same panel↔brain protocol v1. The panel is rebuilt
around a 4×8 Choc grid instead of the MX piano row; the pots are dropped
(the 4 encoders cover parameter editing). **Software is nearly
identical**: same app binary, same firmware skeleton, one build-flag
panel variant per hardware.

## Locked decisions

- **Switches**: Kailh Choc low-profile, ~14 mm pitch, hot-swap. MX
  requirement dropped.
- **Grid LEDs**: all 32 keys lit (HT16K33), pattern + playhead mirror as
  in NSR-1.
- **Pitch/mod thumbstick**: stays, on ADS1115 as in NSR-1.
- **Crossfader**: stays (the NSR-1 data slider, repurposed/mix duty).
- **Pots**: CUT/RES/A/D/S/R dropped — 4 pageable encoders take over.
- **Spacebar**: the space key of the quasi-keyboard — the 4×8 grid
  doubles as a text-entry keyboard (project/pattern naming); the wide
  bar types space. Semantics live in the brain (EditBox widget).
  Built as one Choc switch under a wide ~3u (~42 mm) low-profile cap.
- **Layout, top to bottom**: mic hole → screen → 4 soft keys (equally
  spaced under screen) → 4 encoders → transport + < / > on one line →
  4×8 grid → SHIFT-L, spacebar, SHIFT-R.

(J) = pitch/mod thumbstick — left of the grid, vertically centered on
the grid rows (synth pitch-wheel position). (F) = crossfader —
vertical, right of the grid, same centerline: a two-thumb performance
strip flanking the grid. Default mapping is top = A, bottom = B; any
other macro assignment stays brain-side.

## Hardware deltas vs NSR-1 rev A

Architecture unchanged: `Pi ──USB(OTG)── [Pico] ──I²C── peripherals`,
Pico stays bus master at 400 kHz on GP4/GP5. **Pico pin map is reused
verbatim** (encoders GP0–3/6–9 A/B, GP10–13 pushes; GP16/17 UART header
for rev B).

### I²C map (one bus, 400 kHz)

| Addr | Device | Count | Role |
|---|---|---|---|
| 0x20 | MCP23017 | 1 | grid keys 0–15 (rows 1–2: GPA0–7, GPB0–7) |
| 0x21 | MCP23017 | 1 | grid keys 16–31 (rows 3–4: GPA0–7, GPB0–7) |
| 0x22 | MCP23017 | 1 | function keys (13 inputs, 3 spare) |
| 0x48 | ADS1115 | 1 | AIN0 = thumbstick X (bend), AIN1 = Y (mod), AIN2 = crossfader, AIN3 → GND |
| 0x70 | HT16K33A | 1 | 32 grid LEDs, driver only |

Three expanders, same count as NSR-1 — the MCP23017 has 16 I/O pins, so
45 keys need all 48. One ADS1115 instead of three. Bring-up I²C scan
must list exactly: `0x20 0x21 0x22 0x48 0x70`.

### Key budget — 45 inputs

| Index | Note | Key |
|---|---|---|
| 0–31 | 36–67 | grid, row-major (top-left = 0) |
| 32, 33, 34 | 68, 69, 70 | PLAY, STOP, REC |
| 35 | 71 | MODE |
| 36, 37 | 72, 73 | < , > |
| 38–41 | 74–77 | soft keys S1–S4 |
| 42, 43 | 78, 79 | SHIFT-L, SHIFT-R |
| 44 | 80 | SPACE |

MCP #3 pin assignment (pins 0–12): PLAY, STOP, REC, MODE, <, >,
S1–S4, SHIFT-L, SHIFT-R, SPACE. All inputs single-ended on expander
pull-ups, active low — no matrix, no diodes, as rev A.

### LEDs

HT16K33A drives 32 LEDs (COM0–3 × ROW0–7), one per grid key, row-major —
same formula as NSR-1 (`leds.c`: LED i → RAM[i & 7] bit (i >> 3)),
just a larger count. **Series resistors 1 kΩ** (not NSR-1's 470 Ω):
32 × ~3 mA ≈ 96 mA worst case keeps the Pico's ~200 mA external budget
safe; 470 Ω at 32 LEDs would not. The A-variant's 28-SOP brings out
COM0–7 only; ROW0–2 double as the I²C address inputs (left floating →
address 0x70, all 8 ROWs stay usable).

### Panel dimensions (Choc at 14 mm pitch)

- Grid block: 8 × 14 = 112 mm wide; 4 rows + shift/space row = 5 × 14
  = 70 mm tall.
- Thumbstick (left margin) and vertical crossfader (right margin)
  flank the grid, both centered on its rows.
- Panel: **180 × 210 mm** (to-scale mockup: `nsr2/panel_mockup_nsr2.png`,
  regenerated by `nsr2/mockup_panel.py`) vs NSR-1's 400 × 150 mm — about
  two-thirds of the area in a portrait slab. Screen stays the 4.0"
  480×320 ILI9488 (same 240×160@2× UI) — decided over the 3.5" for
  eyesight.

## BOM delta vs NSR-1

| Change | Items |
|---|---|
| Removed | 2× ADS1115, 6× 10k pots, MX switch kit (39 switches, hot-swap sockets, keycaps) |
| Changed | MX kit → ~29× Choc switches + Choc hot-swap sockets + low-profile keycap set (incl. 1u ×2 + wide spacebar, translucent for under-socket LEDs); 16 → 32 LEDs, 470 Ω → 1 kΩ; HT16K33 → HT16K33A |
| Kept | Pico, 3× MCP23017, 1× ADS1115, thumbstick, 60 mm slide pot (crossfader), 4× EC11 encoders, mic capsule → codec |

Net: panel electronics land meaningfully below NSR-1's, dominated by
the MX→Choc kit swap. Power switch, LiPo, PowerBoost, display, codec
and Pi side are untouched.

## Firmware plan

One codebase, build-flag panel variant (`PANEL_NSR1` / `PANEL_NSR2`):

| File | Delta |
|---|---|
| `board_config.h` | NSR-2 `KEY_CHIPS` (3 chips, same count as NSR-1 — new maps), LED count 32, 1× ADS1115 channel map, default velocity source |
| `config.c` | power-up velocity source = fixed 0x08 @ 100 (crossfader is mix duty, not velocity); REPLY feature mask gains bit 3 |
| `keys.c` | chip count stays 3 (no logic change) |
| `leds.c` | count 16 → 32, same RAM formula |
| `ads1115.c` | 9 channels → 3, board-driven |
| `encoder.c`, `midi.c`, `config.h` SysEx layer, `main.c`, TinyUSB | unchanged |

## Protocol notes (v1, unchanged mechanics)

- Key → note mapping stays `note = 36 + index`; the NSR-2 index table
  above replaces NSR-1's.
- **CC 26 = crossfader** (the old "data slider" source), CC 1 =
  thumbstick Y, pitch bend = thumbstick X — same numbers as NSR-1.
- REPLY feature mask: bit 3 = "32-grid layout (NSR-2)". A brain gates
  its grid mapping on this bit at the QUERY handshake — **one brain
  binary serves both panels**, which is what makes the software
  "nearly identical" rather than "forked".
- Velocity source codes apply unchanged; NSR-2 defaults to fixed 100
  and the brain may SET_VELOCITY_SOURCE to the crossfader (0x00) or
  host register (0x09) as on NSR-1.

## Brain-side mapping (semantics)

- **Step mode**: 32 grid keys = 2 bars of 16ths, or 4 tracks × 8 steps
  (pageable, as NSR-1's 16-step window logic); shift+grid = track
  select / mute / scene launch as NSR-1.
- **MODE** toggles play ↔ step ↔ text entry — a toggle, not a
  shift-hold, so both hands stay free to play (NSR-1 rule).
- **Play mode**: scale-locked isomorphic layout on the 4×8 grid (NSR-1's
  chromatic piano has no grid equivalent).
- **Text entry**: grid = QWERTY-flavored quasi-keyboard (4×8: QWERTYUI /
  ASDFGHJK / ZXCVBNM␣␣ / punctuation+enter+backspace), spacebar types
  space — feeds the existing EditBox/VirtualKeyboard flow.
- Emulator first, as always: `--panel=nsr2` sim profile rendering the
  4×8 layout, before any PCB exists.

## Resolved design calls

1. **MODE** — 6th key on the transport line (index 35 / note 71).
2. **Crossfader** — vertical at the grid's right edge, centered on the
   grid rows; fits the ~36 mm side margin where a horizontal 60 mm
   fader would force a full-width row and a taller panel.
3. **Thumbstick** — left of the grid, same centerline; synth
   pitch-wheel position, reachable by either hand's thumb, clear of
   the shift/space row.
4. **Screen** — 4.0" (eyesight priority over ~15 mm width saving).
5. **Spacebar** — one Choc switch under a wide (~3u) cap; slight cap
   tilt at the extremes is acceptable for a text-entry key.
